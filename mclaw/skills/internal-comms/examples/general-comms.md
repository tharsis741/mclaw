# 其他办公沟通

从上下文识别受众、目的、语气和格式。已有材料足以写稿时直接开始；仅对影响实质内容的缺口提问，不重复确认已知信息。

按沟通目的选取有用的内容：

| 类型 | 读者最需要知道的内容 |
| --- | --- |
| 项目或管理层汇报 | 当前状态、关键成果、相对计划的偏差、业务影响、需要决策的事项和下一步 |
| 内部通知 | 发生什么变化、适用对象、何时生效、需要采取的行动、已有联系人或办理路径 |
| 故障通报 | 已确认的现象和影响范围、已知时间线、当前处理状态、下一次更新安排（已有时） |
| 协作请求 | 背景与目的、具体需要的支持、交付物、已有截止安排和相关材料 |

先交代最重要的信息，再给背景与证据。句子尽量明确施事者；用户有公司模板或口吻要求时保留。结构按内容取舍，不机械填满所有字段。

对故障原因区分已确认、排查假设和待核实，不把暂时恢复写成问题彻底解决。对协作安排区分提出请求与对方已经承诺，负责人和截止日期只使用材料中明确的信息。

草稿中的待确认项应醒目标记；只影响背景的缺口可写在稿外。输出可直接使用的稿件，附必要来源，不附写作过程。
