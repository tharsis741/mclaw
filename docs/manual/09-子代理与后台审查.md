# 子代理与后台审查

## 子代理委派

M-Claw 可以把互相独立的子任务交给隔离子代理，再由主 Agent 汇总结果。委派适合多模块分析、并行资料整理或边界清晰的实现任务。

```text
# 委派并行子任务：
并行检查这个项目的命令系统、Scheduler 和安全层，最后给出统一报告。
```

子代理默认使用受限工具集，主要开放终端、文件和只读 Skill 发现能力。源码中的委派工具支持最多 5 个子任务；具体并发还受运行时资源和配置限制。

每个子任务有独立上下文、迭代次数和超时。主 Agent 会等待结果并进行综合，而不是简单拼接输出。

## 中断与生命周期

用户中断主任务时，取消信号会传播给正在执行的子代理和结果综合线程。运行时会跟踪工作线程，避免子代理仍在写文件时提前结束主回合。

## 后台审查

M-Claw 在任务完成后可以启动两类后台审查：

- 记忆审查：判断是否需要更新长期记忆或用户画像。
- Skill 演化审查：判断已使用 Skill 是否产生了可复用经验。

后台审查与主任务结果分离，使用辅助模型配置和受限工具白名单。它用于沉淀经验，不负责继续执行用户尚未授权的新任务。
