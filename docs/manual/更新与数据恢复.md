更新需要保持 Python 源码、依赖和前端静态资源一致，并重新启动后台。Windows 与开鸿的完整更新命令见[项目中文说明](../../README.zh-CN.md#更新)。

## 更新前备份

1. 确认原 Python 环境与源码路径，记录当前版本或提交，保存本地源码修改。
2. 检查正在执行的任务，运行 `mclaw stop` 并等待收尾。
3. 运行 `mclaw status` 确认后台已停止；开鸿使用 `run mclaw stop`、`run mclaw status`。
4. 备份整个应用数据目录，并单独备份目录外的工作区。
5. 保留旧源码版本、对应静态资源和依赖环境记录。

应用数据目录优先使用 `MCLAW_HOME`，未设置时采用以下默认位置：

| 平台 | 默认应用数据目录 |
| --- | --- |
| Windows | `%USERPROFILE%\.mclaw` |
| Kaihong OS / M-Robots OS | `/data/local/tmp/.mclaw` |
| 其他受支持的桌面系统 | `~/.mclaw` |

完整备份应保留隐藏文件及所有子目录，包括 `config.yaml`、`.env`、会话数据库、技能、记忆、附件、检查点、计划与渠道数据。备份包含凭据和私人内容，应存放在受控位置。

Windows 可在停服后将整个数据目录复制到一个新的备份目录。开鸿可在电脑通过 HDC 导出，例如：

```powershell
hdc file recv /data/local/tmp/.mclaw C:\backups\mclaw-home-before-update
```

自定义了 `MCLAW_HOME` 时替换源路径，备份目标使用新的目录名。复制后核对隐藏文件、数据库和技能等原有内容；运行中的数据库可能有 WAL 文件，停服后复制整个目录可保持数据一致。

## 更新与检查

Windows 在原源码目录和 Python 环境中更新依赖并重新构建前端。开鸿在电脑更新并构建后，将同版本源码与完整的 `mclaw/web/static/` 覆盖到设备原源码目录，在该目录执行 `run python3 -m pip install -e .`，然后启动 M-Claw。

继续使用原应用数据目录，已有配置会被读取，通常无需重新运行设置向导。启动后检查：

- 原有供应商、凭据状态、技能及自行修改的内容。
- 历史会话、附件和工作区文件。
- 定时计划的时区、启停状态、投递位置和下次运行时间。
- 一次简单对话任务及运行检查结果。
- 开鸿设备上的中文输入、附件、录音和可信设备协作。

页面仍显示旧内容时，确认前端重新构建、后台重新启动，并刷新浏览器。

M-Claw 首次打开已有 `state.db` 前，会创建 `backups/before-web-v1.state.db` 并校验；该文件已存在时保留原副本。应用控制状态另存于 `application.sqlite3`，日常恢复仍需完整数据备份。提示“应用数据来自更新版本”时，使用匹配版本或对应备份。

## 恢复旧版本与数据

1. 停止当前后台，另行保存当前数据和工作区，保留升级后产生的内容。
2. 恢复此前的源码版本与配套静态资源，在原 Python 环境重新安装。
3. 将升级前的完整数据备份先恢复到独立目录，核对后替换原数据目录，保持 `MCLAW_HOME` 一致。
4. 按需恢复外部工作区；不要将不同时间点的数据目录混合覆盖。
5. 运行环境检查，启动后按上面的检查项验收。

恢复备份会将会话与计划状态退回备份时点。外部消息、远端操作和工作区文件需要分别核对；恢复调度前检查可能重复执行的计划。程序回退不会自动回退 Python 依赖。
