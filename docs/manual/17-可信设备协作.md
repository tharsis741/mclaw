# 可信设备协作

可信设备协作是 M-Robots OS/Kaihong OS 的平台能力。M-Claw 基于分布式软总线建立可信设备通信，并使用 A2A Task 语义组织远端 Agent 的任务状态、流式进展、补充输入、取消和结果返回。

Windows 和 Linux 不显示可信设备协作的 Setup 选项和设备命令。

## 启用能力


在 “M-Claw 可选能力” 页面选择：

```text
[✓] 可信设备协作 - 发现并连接 OpenHarmony 可信设备，允许双方 M-Claw 通信并使用对方设备上的工具。
```

M-Claw 会检查系统版本、CPU ABI、DSoftBus 组件和运行权限。检查通过后，后续启动会快速校验并自动激活该能力。

两端设备均需完成 Setup 并运行 M-Claw：

```bash
run mclaw
```

## 查看设备

在 M-Claw TUI 输入：

```text
/devices
```

界面按用途展示设备：

| 区域 | 含义 |
| --- | --- |
| 当前设备 | 本机名称和供其他设备识别、选择的短标识 |
| 已连接设备 | 已建立系统信任的设备，以及连接和 Agent 就绪状态 |
| 可配对设备 | 当前扫描到且尚未建立信任的设备候选 |

常见状态：

- **可通信**：对端 M-Claw Agent 已就绪，可以执行远端任务。
- **正在连接或重连**：系统信任存在，Runtime 正在建立或恢复 Agent 通道。
- **Agent 未就绪**：对端 M-Claw 尚未运行、未启用可信设备协作，或数据通道尚未建立。

设备列表依赖系统发现状态。M-Claw 刚启动时可以等待数秒后再次执行 `/devices`。

## 配对设备

1. 在两台设备上运行 M-Claw。
2. 在发起端输入 `/pair`。
3. 根据设备名称和候选短标识选择目标设备。
4. 确认发起系统配对。
5. 按两端系统提示完成用户确认和 PIN 验证。
6. 再次输入 `/devices`，等待目标设备显示“可通信”。

配对建立的是 OpenHarmony 系统信任。M-Claw 使用该信任关系认证对端，不通过普通网络地址代替系统身份。

## 解除配对

输入：

```text
/unpair
```

选择设备并确认后，M-Claw 会解除由本应用建立和管理的系统信任关系。解除完成的设备可以在后续扫描中重新作为配对候选出现。

## 调用远端 Agent

设备显示“可通信”后，直接用自然语言描述目标设备和任务。M-Claw 会选择可信设备协作工具并建立远端 Task。

```text
# 让对端M-CLAW执行设备信息检查
让 Qihan 的电脑检查当前系统信息，并总结可用的开发工具。
```

```text
# 让对端M-CLAW分析程序运行日志
让设备 31a9765f 分析日志中的错误原因，并把建议返回给我。
```

请求端 TUI 会显示远端任务状态，包括：

```text
- 远端 M-Claw 思考中...
- 远端 M-Claw 任务进展：
```

远端 Task 具有独立生命周期。任务持续运行时，Runtime 会续期任务所有权；短暂断线恢复后会继续查询或订阅同一 Task。远端请求补充文字或文件时，M-Claw 会将请求带回当前会话，用户可以在下一条指令中提供所需内容并继续同一个 Task。

在请求端按 `Ctrl+C` 会取消当前等待，并向被调用端传播 Task 取消；被调用端会停止并回收该任务启动的终端进程。

## 发送文件和图片

在任务中明确给出本机文件路径，M-Claw 可以将文件副本随 Task 发送给远端 Agent：

```text
把 /data/local/tmp/report.txt 发给 Qihan 的电脑，让远端 Agent 检查内容并返回修订后的文件。
```

文件会分块传输并校验长度和 SHA-256。被调用端将通过校验的文件保存到该 Task 的独立工作区，Agent 操作的是工作副本。

图片同样可以作为任务输入：

```text
让远端 Agent 分析 /data/local/tmp/device-panel.png，说明画面中的设备状态。
```

图片分析需要被调用端配置可用的视觉模型或视觉工具。

当前文件边界：

- 单个输入文件最大 16 MiB。
- 每个 Task 的输入文件累计最大 64 MiB。
- 单个返回文件 Artifact 最大 16 MiB。
- 每个 Task 最多声明 31 个初始输入路径。

## 共享目录范围

当任务明确给出目录路径时，该目录会成为只读源范围。目录内容不会在任务开始时整体发送；远端 Agent 可以根据任务需要：

1. 分页查看目录结构。
2. 按文件名或有界文本内容搜索。
3. 选择明确文件并获取到远端 Task 工作区。

```text
让远端 Agent 检查 /data/local/tmp/project 中与登录流程有关的代码，需要哪些文件就按需读取。
```

远端 Agent 只能修改获取到本设备后的工作副本，不能直接写入调用端原目录。

## 接收结果文件

远端 Agent 可以把结构化结果或工作区文件声明为 Artifact。M-Claw 会将文件分块传回请求端，校验后保存到可信设备协作工作区，并把本机绝对路径、大小和 SHA-256 提供给请求端 Agent。

Artifact 不会自动覆盖请求端原文件。用户可以检查结果后，再决定是否通过本机文件工具应用修改。

## 权限与运行边界

- 设备身份和通信准入基于 OpenHarmony 系统信任关系。
- 远端 Agent 使用被调用设备上的运行身份、工具配置和 PathPolicy。
- 请求端仅共享当前任务明确列出的文件或目录范围。
- 目录范围保持只读，获取到远端的文件成为独立工作副本。
- 两端 M-Claw 需要保持运行，设备状态需要达到“可通信”。

## 故障排查

### Setup 中没有可信设备协作

该选项只在受支持的 M-Robots OS/Kaihong OS 运行环境显示。运行 `run mclaw doctor` 检查系统识别和平台能力。

### `/devices` 显示 Runtime 或 Worker 未就绪

启动后等待数秒并重试。持续未就绪时运行 `/doctor`，检查 DSoftBus 系统组件、运行权限和 Runtime 诊断日志。

### 已配对但不能执行 Agent 任务

在两端确认 M-Claw 正在运行、可信设备协作已启用，并检查 `/devices` 是否显示“可通信”。“正在重连”或“Agent 未就绪”表示 Agent 数据通道尚未完成。

### `/pair` 超时

检查被连接端是否出现系统配对确认，按系统提示完成确认和 PIN 输入。完成后重新运行 `/devices` 查看信任与 Agent 状态。

### 文件发送失败

确认路径存在、当前 Agent 有权读取、文件符合大小限制，并检查两端数据通道。目录任务应明确共享目录路径，由远端按需获取文件。

更多环境诊断见[平台适配、诊断与故障排查](15-平台适配诊断与故障排查.md)。
