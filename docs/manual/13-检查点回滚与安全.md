# Checkpoint、Rollback 与安全

## 安全模型

M-Claw 1.0.0 不带有权限沙箱。工具使用当前操作系统用户权限运行，但通过 PathPolicy、Scoped Secret、变更检测、Checkpoint 和操作日志降低误操作风险。

## PathPolicy

PathPolicy 保护 M-Claw Home、凭据文件、系统关键路径和危险递归操作。它会解析文件工具目标、终端工作目录以及命令中的潜在变更路径。

首次在工作区执行风险操作时需要确认信任。绝对路径和工作区外路径仍可能因策略被拒绝。

## Scoped Secret

凭据按 `skill`、`tool`、`runtime` 或 `channel` 作用域授权。子进程环境会移除未授权的敏感变量；已授权密钥如果出现在输出中会被脱敏。

## Checkpoint

CheckpointManager 使用 M-Claw Home 中的共享 shadow Git 存储，不会在用户项目中创建或修改 `.git`。文件写入、修改、删除及识别出的破坏性终端操作会在执行前创建快照。

```text
/checkpoints
/checkpoints status
/checkpoints prune
/checkpoints clear --yes
```

- `status`：显示存储状态和统计。
- `prune`：清理过期或孤儿快照。
- `clear --yes`：明确确认后清空 Checkpoint 存储。

默认最多保留 50 个快照、总大小 500 MB、单文件 10 MB，并清理超过 30 天的内容。

## Rollback

```text
/rollback
/rollback <序号>
/rollback undo
/rollback recover [恢复点ID]
/rollback restore <序号>
/rollback turn <序号或turn_id>
/rollback diff <序号>
/rollback ops
/rollback ops <序号>
/rollback ops diff <序号>
/rollback project
/rollback project diff <序号或hash>
```

`/rollback` 显示最近可撤销的操作或操作组。恢复时会检查当前文件状态；如果文件在目标操作之后又发生变化，会创建冲突备份或拒绝不安全覆盖。

- `<序号>`：撤销列表中的操作。
- `undo`：恢复最近一次已经撤销的变更。
- `recover`：恢复此前被中断的文件恢复事务。
- `restore`：重新应用一组已经撤销的变更。
- `turn`：按 Agent 回合恢复一组操作，并根据配置同步恢复聊天上下文。
- `diff`：查看单操作组的差异；组合变更可进一步使用 `ops diff`。
- `ops`：查看和操作底层文件操作记录。
- `project`：查看原始项目 Checkpoint；恢复前会再次要求确认。
- `project diff`：预览项目级回滚差异。

高级使用时可通过 `--dir` 指定安全工作区，并通过上下文选项控制聊天上下文恢复。正常使用优先从无参数 `/rollback` 展示的列表和提示继续操作。

如果回滚创建文件的操作，对应新文件可能被删除；如果目标后来又被修改，协调器会先检查状态。

## 平台限制

Kaihong OS、M-Robots OS 和识别为 OpenHarmony 的 Kaihong Runtime 当前禁用 Checkpoint，因此 `/checkpoints` 和依赖快照的恢复能力不可用。所有平台都不应把当前安全层理解为容器或虚拟机隔离。
