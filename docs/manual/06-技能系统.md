# Skill 系统

## 功能设计

Skill 是 M-Claw 的可复用能力单元。一个完整 Skill 可以包含：

- `SKILL.md`：功能边界、使用条件和执行流程。
- `mclaw_skill.yaml`：名称、描述、平台、依赖和能力元数据。
- `skill_evolution.json`：适配结果、偏好、失败经验和注意事项。
- `scripts/`、`references/`、`assets/`：执行脚本、参考资料与模板。

M-Claw 启动时同步内置 Skill，并建立启用 Skill 的轻量索引。只有在使用某个 Skill 时才读取其完整说明和相关资源。

## 查看 Skill

```text
/skills
/skills list
```

输出会列出已启用 Skill、简短描述和对应的动态命令。

## 调用 Skill

```text
/<skill-name>
/<skill-name> <任务描述>
```

只输入 Skill 名称会把该 Skill 的规则加载到当前 Agent 上下文；同时提供任务描述时，M-Claw 会加载 Skill 并立即处理该任务。

```text
# 调用天气 Skill：
/weather 查询深圳明天的天气
```

内置命令拥有 Slash 命名空间优先权，同名 Skill 不会覆盖 `/help`、`/model` 等内置命令。

## 搜索外部 Skill

M-Claw 的外部 Skill 搜索默认连接 `skills.sh` 目录。搜索接口不需要 API Key，也不会调用普通网页搜索。返回结果只保留能够从公开 GitHub 仓库安装的 Skill，候选信息包括：

- Skill 名称和描述
- skills.sh 页面与目录 ID
- GitHub 仓库
- Skill slug
- 安装量

搜索既支持准确名称，也支持能力描述。M-Claw 会判断用户是在查找指定 Skill，还是在根据用途寻找候选，并按照相应方式整理结果。

```text
# 按能力搜索外部 Skill：
帮我搜索能够生成、编辑和检查 PDF 的外部 Skill。列出候选 Skill、来源和安装量。
```

```text
# 按名称搜索外部 Skill：
帮我搜索 pdf Skill。
```

搜索本身不会下载或安装任何 Skill。M-Claw 展示候选后，需要用户明确选择，才能进入安装准备流程。

```text
# 选择搜索结果：
安装刚才搜索结果中的 pdf Skill。
```

当前没有 `/skill search` Slash Command。外部 Skill 搜索由 Agent 根据用户的查找或推荐需求调用 `skill_search`；`/skills` 只负责查看已经启用的本地 Skill。

## 安装外部 Skill

```text
/skill install <source>
```

`<source>` 支持以下来源：

| 来源 | 格式 | 说明 |
| --- | --- | --- |
| skills.sh | `https://skills.sh/<owner>/<repo>/<skill>` | 推荐格式，可从多 Skill 仓库精确选择目标 Skill |
| GitHub 仓库 | `https://github.com/<owner>/<repo>` | 仓库根目录本身需要构成有效 Skill 包 |
| GitHub 目录 | `https://github.com/<owner>/<repo>/tree/<branch>/<path>` | 指向仓库中的具体 Skill 目录 |
| GitHub 文件 | 指向 `SKILL.md` 的 `blob` URL | 安装其所在目录 |
| ClawHub | `https://clawhub.ai/<owner>/skills/<slug>` | 同时兼容旧版 `<owner>/<slug>` 链接 |
| 本地目录 | 本机 Skill 文件夹路径 | 目录不能是符号链接 |

### 从 skills.sh 安装

skills.sh URL 必须包含三段标识：GitHub owner、repository 和 Skill slug。

```text
# 安装 skills.sh Skill：
/skill install https://skills.sh/anthropics/skills/pdf
```

M-Claw 会从对应公开 GitHub 仓库下载默认分支，不需要 skills.sh API Key，也不需要调用 GitHub API 查询默认分支。仓库包含多个 Skill 时，运行时优先匹配 `SKILL.md` frontmatter 中的 `name`，否则匹配目录名称，只复制选中的 Skill 包。

如果没有找到对应 slug，或者仓库中存在多个同名 Skill，安装会停止，不会任选一个继续。

### 从 GitHub 安装

单 Skill 仓库可以使用仓库地址；多 Skill 仓库建议提供目标目录的 `tree` URL。

```text
# 安装 GitHub 仓库中的 Skill 目录：
/skill install https://github.com/<owner>/<repo>/tree/<branch>/<skill-path>
```

### 从 ClawHub 安装

```text
# 使用当前标准链接安装 ClawHub Skill：
/skill install https://clawhub.ai/<owner>/skills/<slug>

# 使用旧版链接安装 ClawHub Skill：
/skill install https://clawhub.ai/<owner>/<slug>
```

M-Claw 同时支持当前标准 `<owner>/skills/<slug>` 链接和旧版 `<owner>/<slug>` 链接，推荐使用当前标准格式。URL 必须严格符合其中一种结构，多余路径或无效的 owner、slug 会被拒绝。

新版 ClawHub 下载流程会把 owner 贯穿整个解析过程：

1. 使用 owner 和 slug 查询 ClawHub Skill 详情，而不是只按 slug 查询。
2. 校验详情接口返回的 owner 与 URL 一致，避免不同作者使用相同 slug 时选错 Skill。
3. 使用同时包含 `slug` 和 `ownerHandle` 的下载请求获取压缩包。
4. 下载请求跟随 ClawHub 返回的重定向，并以流式方式写入临时文件。
5. 下载失败、超时或被用户中断时，删除未完成的临时压缩包。
6. 解压前检查绝对路径和 `..` 路径穿越，再进入通用的包结构验证、安全扫描和确认流程。

ClawHub 不再是默认搜索源，但已有链接仍可通过 `/skill install` 手动安装。

### 从本地目录安装

```text
# 安装本地 Skill：
/skill install C:\path\to\my-skill
```

本地来源必须是实际目录，不能是文件或符号链接。无论来源如何，包根目录都必须包含 `SKILL.md`；如果没有 `mclaw_skill.yaml`，`SKILL.md` frontmatter 必须包含 `name` 和 `description`。

## 安装准备与确认

`/skill install` 不会把外部内容直接写入已启用 Skill 目录。完整流程如下：

1. 解析来源并下载或复制到 drafting 目录。
2. 验证 `SKILL.md`、名称和包结构。
3. 生成或规范化 `mclaw_skill.yaml` 和 `skill_evolution.json`。
4. 静态扫描依赖提示，只记录可能需要的环境变量名称及来源文件，不读取密钥值。
5. 扫描提示注入、凭据外传、危险删除和持久化等风险模式。
6. 保存安装清单和安全审查结果。
7. 显示 Skill 名称、来源、风险等级、发现项和依赖提示，等待用户确认。
8. 用户批准后，将 drafting 包移动到已启用 Skill 目录并写入安装审计记录。

安全策略判定为危险的社区 Skill 会直接阻止安装，不提供强制启用选项。安全或存疑的 Skill 仍必须由用户确认。

确认时可以输入 `Y`、`yes`、`allow`、`install`、`approve`、`是`、`允许`、`确认` 或 `安装`。输入 `N`、`no`、`cancel`、`reject`、`否`、`取消` 或 `停止` 会删除草稿并取消安装。

同一时间只能处理一个待确认的 Skill。若同名 Skill 已经存在，启用阶段会拒绝覆盖。安装过程中被中断或发生异常时，临时下载和未完成草稿会被清理。

安装准备只识别后续可能需要的凭据，不会收集密钥。Skill 真正执行并需要凭据时，M-Claw 才会通过 Scoped Secret 流程请求授权。

Skill 文件不能绕过 `skill_manage` 随意写入受治理的 Skill 存储。这样可以保持元数据、演化文件和安全检查一致。

## 创建 Skill

```text
/skill creation <需求描述>
```

创建流程会根据需求生成 Skill 草稿，检查名称、目录结构、依赖和声明，用户确认后启用。需求描述应包含目标、输入、输出、平台和必要工具。

## Skill 发现与演化

Agent 可以列出本地 Skill，查看 Skill 文件树与内容，并通过受控管理工具执行安装、编辑和演化更新。外部发现默认使用 skills.sh，ClawHub 链接保留手动安装兼容。后台审查会按配置周期分析 Skill 使用情况，将稳定经验写入 `skill_evolution.json`。

Skill 演化用于沉淀执行经验，不应在没有证据时改变 Skill 的功能边界。
