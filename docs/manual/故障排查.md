先打开“设置 → 运行检查”查看说明。页面打不开时，在原安装环境运行 `mclaw status` 和 `mclaw doctor`；开鸿使用 `run` 前缀。

## 页面与启动

| 现象 | 检查与处理 |
| --- | --- |
| 找不到网页资源 | 在电脑构建前端，确认 `mclaw/web/static/index.html` 存在；Kaihong设备传入整个静态目录 |
| Node/npm 版本不满足要求 | 构建电脑需 Node.js 22.12+、npm 10+，安装后重新打开终端检查 |
| 安装成功但找不到 `mclaw` | 切回安装时的 Python 环境；Windows 可用 `python -m mclaw` 检查入口 |
| 浏览器没有打开 | 使用启动输出中的完整本机链接，开鸿同时检查系统浏览器与 `run` 环境 |
| 默认端口无法连接 | 运行 `mclaw status` 查看实际地址，端口占用时会尝试后续端口 |
| 连接失效或未授权 | 重新运行 `mclaw`，打开带有当前连接凭据的链接 |
| 更新后页面异常 | 确认 Python 源码与静态资源版本一致，重启后台并刷新页面 |

本机地址中的 `127.0.0.1` 指向浏览器所在设备。跨设备任务通过[可信设备协作](设备.md)配置。

## 模型与任务

| 现象 | 检查与处理 |
| --- | --- |
| 无可用模型 | 打开供应商与模型，保存接入、凭据和模型后，在对话中选择 |
| 401 / 403 | 核对密钥、API 区域、服务地址及账户权限 |
| 模型不存在或工具调用失败 | 核对模型标识、接口协议和模型能力，按需使用“获取模型” |
| 首段回复超时或输出中断 | 检查网络与模型服务，按需调整模型行为中的等待时间 |
| 会话被占用 | 在原网页或终端继续操作，或结束其控制后重新打开 |
| 等待授权或补充输入 | 查看当前会话中的路径、凭据或资料请求并处理 |
| 停止后仍显示收尾 | 等待正在运行的工具结束，观察状态后再进行恢复或删除 |

## 工具与外部服务

| 现象 | 检查与处理 |
| --- | --- |
| 工具已开启仍不可用 | 查看运行检查中的依赖、凭据与平台条件，修改后从下一任务验证 |
| 浏览器工具不可用 | 按安装说明补齐 Playwright 和匹配的 Chromium |
| 图片无法识别 | 检查图片理解开关、当前或专用模型能力、文件大小及像素上限 |
| 无法录音 | 检查语音配置、浏览器麦克风权限、设备和录音格式 |
| 文件路径不存在 | 核对路径是否属于后台设备，以及实际工作区位置 |
| 技能安装失败 | 查看来源、网络、同名冲突及安装检查结果 |
| 市场详情或报告缺失 | 查看缓存时间和来源状态，限流解除后再刷新 |
| 计划未执行 | 检查启用状态、时区、下次运行时间及后台是否持续运行 |
| 任务成功但没有投递 | 检查运行记录中的投递结果、目标绑定和渠道连接 |
| 设备已配对但无法执行 | 核对对端在线状态、M-Claw 就绪状态和两端协同开关 |

## 提交问题信息

反馈时提供 M-Claw 版本、源码提交、操作系统或设备/API 版本、Python 与浏览器版本，以及操作步骤、预期结果和实际结果。构建问题补充 Node.js/npm 版本，附上相关截图和诊断报告。

分享前检查内容，隐藏密钥、登录二维码、连接令牌和私人资料。完整应用数据目录包含凭据与历史，不宜作为普通问题附件。
